# G-Shop Console Integration

Launch integration also follows PATCH-LAUNCH-01 / PATCH-CHAIN-01 in the project's
COLLECTION_PATCHES_SPECIFICATION.md. Resolve an explicit patch/build choice before
starting the 3D animation, retain the selected modified edition's save/companion/
rating identity and never re-intercept a derived result. Availability reads only
source/version-bound local metadata prepared by explicit sync/Patches browsing.
Prerequisites need exact ordered declarations and intermediate fingerprints;
never guess chains from titles/readmes or apply independent mods in listing order.
The owner has postponed a distinct hack-specific animation; shared generation
behavior is not evidence that this future variation has been implemented.

Verify patch launch from both ordinary details and the secondary screen, including
an actual started patched game. An accepted Android intent is only handoff evidence.
Use the existing isolated debug package for native chain/failure fixtures; never
install a test entrypoint over the owner's app. Report cached indexed-game coverage
separately from exact original bindings and verified build recipes. A first page
or a synthetic native chain does not establish complete production patch coverage;
missing explicit prerequisite declarations remain unresolved catalogue evidence.
For a large published catalogue, verify that exact path resolution uses bounded
indexed lookups while preserving folder scope, generation, case and duplicate-name
rejection. A cache hit must not repeatedly transfer/decode every sibling's JSON.
Check additive cache migrations against existing recipes and collector/catalogue
checkpoints. Distinguish provider failures from local lookup work and retain the
original resumable operation instead of relaunching it while still running.

Locate the actual G-Shop checkout. Read `docs/SPECIFICATION.md`, the current
`docs/IMPLEMENTATION_PLAN.md` and `docs/IMPLEMENTATION_STATUS.md`, then
`docs/CONSOLE_INTEGRATION_CONTRACT.md`. The latter contains the owner-approved
CI-01..08 rules and per-generation exceptions. If this contract is unavailable,
resolve the checkout/document rather than silently inventing an equivalent.

This skill supplies integration and review technique. It does not activate a new
stage, require a worker, authorize a new console, change scope, introduce approval
ceremony or supersede user/standing instructions. Preserve existing authorization
and the sole active stage. Reload the contract when the owner changes its rules.

## Carry forward the complete existing pipeline

Before integrating another console, read
[the end-to-end pipeline and acceptance checklist](references/console-integration-pipeline.md).
Recover the existing GBA implementation, retained evidence and later owner
decisions before proposing another path. Map every applicable step to the current
console and existing reconciliation ledger. Reuse the working acquisition,
reconstruction, import/publication and recovery lanes; a console-specific renderer
must not bypass them. The owner supplies genuinely missing resources, not a
repeated description of the integration process. Historical evidence establishes
the precedent and permission; verify the new console's actual delivered behavior.

## Full collection coverage; Top 25 testing

Cover **every ROM in the console's collection before moving to another console**.
This applies retrospectively to GBA as well as NES and future integrations.
Top 25 is the native testing sample, never the acquisition/reconstruction,
binding, publication or recovery scope. Keep an exact per-archive/game/edition
resource ledger, distinguishing available, missing, invalid, uncertain, evidenced

their base game's art or claim a model-edition count as unique-game coverage.
Resolve actionable gaps through the complete existing pipeline and hold the

Reconcile all batches and verify full-census bindings/integrity through the normal

Reconcile the complete selected model catalogue against that handoff, including
unchanged original cartons, not only newly reconstructed cohorts. Existing meshes
can be valid while their original panels have never entered normal publication.

source crop hashes. Inspect assembled UV-mapped faces first: a source scan's

Keep damaged/obscured selections out of acceptance and prefer an intact compatible
